# Test Strategy

`test-strategy` 为测试层次、证据范围、运行成本和结构调整期间的测试迁移提供决策规则。它适用于模型、GPU、浏览器、服务、多进程等昂贵环境，也适用于故障注入、测试替身和白盒合同存在争议的情况。

## 调用方式

该 Skill 可以由使用者显式调用：

```text
$test-strategy 请为 Executor 生命周期调整选择测试层次，并说明每层测试能够证明什么。
```

Agent 也可以在以下情况自动加载它：

- 昂贵运行环境的启动、复用或隔离；
- 架构调整引发测试迁移；
- 测试 seam 或测试层次需要选择；
- 测试替身、故障注入或白盒合同需要判断；
- 现有测试结果可能因源码、构建、配置或持久状态变化而失效。

普通代码修改不会触发该 Skill。

## 证据合同

Skill 会在同一 seam 和运行环境的一组测试开始前，用每项默认一行的形式明确：受保护行为、独立预期、选择的测试层次、已有证据、证据缺口、失效条件和最终验证集合。独立预期可以来自规范样例、固定结果、参考实现、不变量或 metamorphic relation。相关判断没有变化时可以复用，避免为每个测试重复说明。

选择测试层次时，直接生产对象适合纯逻辑和状态转换；最低充分真实集成适合跨模块、协议、并发和资源生命周期；真实进程、GPU、模型或服务适合只能在对应机制中出现的行为。

## 测试替身与故障注入

测试替身只替换证据范围之外的外部或昂贵依赖，并且需要说明被排除的行为。缺失证据由相应真实集成补充。项目的 `AGENTS.md` 和测试规范具有更高优先级，因此项目中的绝对禁令会覆盖这里的条件性许可。

故障注入按照真实覆盖范围表述结果。普通异常注入可以证明对应传播和清理路径；CUDA 故障、进程终止和真实硬件失败需要各自机制提供证据。

## 与其他 Skills 组合

- `tdd` 管理 red → green 时序和预先确认的 seam；
- `test-strategy` 管理证据层次、运行成本、测试迁移和证据失效；
- `write-maintainable-code` 管理 green implementation 内部质量；
- `implement` 与 `code-review` 管理施工和独立审查流程。

显式组合示例：

```text
$implement $write-maintainable-code $test-strategy 实现 IPC 关闭协议，并选择最低充分真实集成。
```

该 Skill 不会自行启动其他 Skill，也不会改变已经接受的接口、验收条件或发布权限。
